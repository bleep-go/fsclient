# fsclient 1.2.0 — список изменений

Дата: 27.11.2026

## 1.2.0

- Версия поднята до **1.2.0**.
- Окно настроек переведено на системный acrylic: всё, что находится за окном,
  размывается DWM. Собственные слои с обоями убраны, дублирования фона больше нет.
- Панели, поля ввода, кнопки и слайдер настроек приведены к общей теме лаунчера.
- Все настройки TG WS Proxy перенесены под кнопку «Параметры» под кнопкой запуска;
  на странице остались только статус, ссылка и журнал.
- Сохраняются последний выбранный релиз zapret/TG WS Proxy и последняя запущенная
  стратегия. Под кнопкой запуска zapret появилась кнопка повтора последней стратегии.
- При первом запуске показывается экран подготовки с пояснениями.
- Встроенное приложение распаковывается один раз в `Program Files\fsclient\app`, а не в
  `%LOCALAPPDATA%` — это снижает риск ложных срабатываний антивирусов.
- Папка конфига теперь `%LOCALAPPDATA%\fsclient` без номера версии; старые настройки
  переносятся автоматически. Папка данных по умолчанию — `%ProgramFiles%\fsclient\data`.
- Добавлено самообновление лаунчера: проверка GitHub Releases, уведомление кнопкой,
  скачивание `fsclient.exe` с проверкой SHA-256 и замена через `updater.exe`, который
  перезапускает лаунчер и закрывается. `updater.exe` не запрашивает UAC — он наследует
  права от уже elevated лаунчера.

## 1.1.0

Дата: 26.11.2026

## Главное

- Полный переход фронтенда с Python/PyQt6 на **C# / WPF**. Нативный бэкенд
  `cpp/fs_backend.dll` не переписывался — C# вызывает его через P/Invoke,
  сигнатуры взяты из `cpp/backend.h`.
- Версия поднята до **1.1.0**.

## Исправления

- Исправлена ошибка Telegram «The proxy link is invalid» и неудачные handshake
  с DC: `RandomNumberGenerator.GetHexString(16)` возвращает 16 **символов**, а
  не 16 байт, поэтому секрет имел длину 16 вместо требуемых 32 hex-символов.
  Теперь генерируется 32 символа; существующий короткий секрет перезаписывается
  при подготовке конфига, а `tg://proxy` всегда строится из валидного секрета.
- Увеличена высота полей ввода и добавлена прокрутка по горизонтали; поле
  `tg://proxy` переносится на несколько строк, подпись секрета больше не
  перекрывает поле.
- Исправлено падение zapret при запуске любой стратегии: `winws.exe`
  запускался напрямую, минуя `service.bat load_user_lists`, из-за чего не
  создавались `lists\*-user.txt` и zapret завершался с ошибкой
  `failed to register ipset '...ipset-exclude-user.txt'`. Бэкенд теперь создаёт
  недостающие пользовательские списки сам (не перезаписывая существующие)
  при запуске стратегии, установке службы и запуске службы.

## Настройки

- В правом верхнем углу окна добавлена кнопка ⚙ с окном настроек.
- Раздел «Общие»: выбор папки данных. По умолчанию
  `%ProgramFiles%\fsclient\1.1.0`. При смене папки файлы копируются,
  проверяются и только потом старая папка удаляется; конфиг остаётся в
  `%LOCALAPPDATA%\fsclient\1.1.0`. При первом запуске скачанные релизы
  переносятся из старой папки автоматически.
- Раздел «Внешний вид»: размытие фона, заголовок окна и своя картинка фона.
- Добавлен `logs\launch.log` с логом последних трёх запусков.

## TG WS Proxy

- Карточка «TG-WS-Proxy» в боковом меню больше не заглушка: открывается
  полноценная страница управления официальной Windows-сборкой Flowseal.
- Версии TG WS Proxy загружаются через GitHub API репозитория
  `Flowseal/tg-ws-proxy`; скачивание идёт с прогрессом и проверкой SHA-256,
  указанного в релизе. Есть резервный список версий на случай недоступности API.
- Лаунчер сам создаёт портативную папку `TgWsProxy_data`, пишет `config.json`
  (host, port, secret, DC, CF/H2, флаги), отключает проверку обновлений и
  диалог первого запуска оригинального приложения.
- В нативном бэкенде добавлены `fs_tgws_start`, `fs_tgws_stop`, `fs_tgws_state`:
  exe Flowseal запускается скрыто и привязывается к Job Object; stop завершает
  дерево процессов, состояние опрашивается лаунчером.
- На странице доступны запуск/стоп/перезапуск, редактирование конфига,
  генерация нового secret, копирование и открытие `tg://proxy`, открытие
  папки версии и `proxy.log`, журнал прокси и ссылка на релизы.
- Папка данных TG WS Proxy (`tg-ws-proxy\releases`) переносится вместе с
  остальными данными при смене папки. Настройки заблокированы, пока активен
  zapret или TG WS Proxy.

## Интерфейс

- Матовое стекло поверх фона (размытие увеличено до `Radius=18`).
- Скруглённый прогресс-бар с плавной анимацией заполнения.
- Выпадающий список релизов открывается по клику в любой точке, а не только
  по стрелке; меню тоже оформлено в стиле приложения.
- Появилось интро `FSCLIENT` с анимацией появления букв.
- Анимации контекстного меню и переходов между страницами.
- Кнопка открытия папки релиза приведена к общему стилю «стеклянных» панелей.
- Кастомное тёмное меню в системном трее вместо системного.

## Запуск и совместимость

- Раньше EXE был framework-dependent и молча не запускался без .NET 10 и DLL
  рядом. Теперь это **один `fsclient.exe`**: нативная проверка наличия
  **.NET 10 Windows Desktop Runtime** вынесена наружу, а WPF-приложение со
  всеми зависимостями вшито внутрь того же файла как ресурс.
- Если runtime не найден — сообщение и переход на официальную страницу
  скачивания `https://dotnet.microsoft.com/download/dotnet/10.0`.
- Если runtime есть — приложение распаковывается в
  `%LOCALAPPDATA%\fsclient\1.1.0\app\` и запускается с запросом прав
  администратора через UAC. Рядом с EXE ничего не нужно.
- Иконка `fsclient.ico` встроена прямо в `fsclient.exe` (раньше EXE показывал
  стандартную иконку).
- Исправлена ошибка запуска на «чистых» ПК: лаунчер больше не требует
  `libwinpthread-1.dll` рядом с EXE — MinGW-рантайм вшит статически. В сборку
  добавлена проверка, что во внешних импортах не осталось DLL MinGW.
- При скрытии в трей включается «режим сна» WPF: отключается размытие фона,
  `VisualBrush` матовых панелей и кэш декодированной картинки, после чего
  вызываются GC и `EmptyWorkingSet`. Опрос состояния замедляется до 10 с, но
  закачки, служба и уведомления продолжают работать; при открытии окна всё
  возвращается.
- Приложение по-прежнему требует Windows x64 и прав администратора.

## Структура проекта

- Все исходники перенесены в корень репозитория; папка `fsclient-csharp/`
  удалена.
- Удалены Python-файлы (`main.py`, `ui_main.py`, `widgets.py`, `modals.py`,
  `theme.py`, `backend_ctypes.py`, `backend_mock.py`), PyInstaller-скрипты
  и дублирующий проект `src/FsClient`.
- `build.bat` стал единой точкой сборки: C++ DLL → публикация WPF → сборка
  одного EXE с встроенными файлами приложения.
- Обновлены `README.md`, `.gitignore`, добавлен этот `CHANGELOG.md`.
