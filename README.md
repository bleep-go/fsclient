# fsclient 1.3.0

![fsclient](assets/fsclient.png)

Лаунчер для **zapret** и **TG WS Proxy** на C# / WPF с нативным C++-бэкендом.
Python-версия больше не используется — фронтенд полностью переписан на C#.

## Суть программы

`fsclient` — это оболочка над проектами [Flowseal/zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube)
и [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy).
Для zapret лаунчер скачивает готовые релизы, показывает версии и стратегии,
запускает `winws.exe` (1.x) или `winws2.exe` (2.x) либо устанавливает службу.
Для TG WS Proxy лаунчер скачивает официальную Windows-сборку, сам пишет ей
`config.json`, запускает/останавливает процесс и показывает ссылку для
подключения Telegram — то есть управляет готовым exe Flowseal, не реализуя
свой MTProto-прокси.

**Все релизы скачиваются с оригинального репозитория
[Flowseal/zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube/releases).**
Этот проект не хранит и не перепаковывает бинарники zapret — он только
загружает официальные релизы через GitHub API и распаковывает их в папку
`releases\` внутри папки данных (по умолчанию `%ProgramFiles%\fsclient\data`).

### Что умеет

- Список актуальных релизов с GitHub + резервные теги `1.10.0`–`1.10.4` и `2.0.0-rc`.
- Пре-релизы видны в списке, но помечаются; рекомендуется последний стабильный 1.x,
  пока 2.x не стал стабильным.
- Скачивание и распаковка релиза с прогресс-баром.
- Выбор стратегии и запуск через `winws.exe` (1.x) или `winws2.exe` (2.x)
  без окна консоли; поддерживаются оба формата стратегий.
- Установка / замена / удаление службы zapret.
- Опрос состояния каждые 1.8 с, кнопка «Стоп», мини-консоль вывода.
- **TG WS Proxy:** список версий с GitHub, скачивание официального exe
  (с проверкой SHA-256 из релиза), управление процессом через нативный бэкенд,
  редактирование конфига, генерация secret и ссылки `tg://proxy`, журнал и
  меню действий на отдельной странице.
- Матовое стекло, плавный прогресс, анимации и кастомное меню в трее.
- Сворачивание в трей при закрытии окна.
- Проверка обновлений самого лаунчера на GitHub: если вышла новая версия,
  появляется кнопка уведомления; скачивание и замену делает `updater.exe`.
  Если репозиторий из `settings.json` (`UpdateRepo`) ещё не создан или приватный,
  проверка молча пропускается и не засорёт лог.

## Требования

- Windows **x64**.
- **.NET 10 Desktop Runtime** (не SDK, именно Desktop Runtime).
- Права администратора нужны только для zapret (WinDivert и служба).
  TG WS Proxy работает без elevate.

Если .NET 10 не установлен, `fsclient.exe` покажет сообщение и сразу откроет
[официальную страницу скачивания](https://dotnet.microsoft.com/download/dotnet/10.0).
Проверка сделана нативным кодом до запуска WPF-приложения — сам .NET в EXE
не вшит.

## Запуск

Это **один файл**:

```bat
dist\fsclient.exe
```

Внутри EXE находятся и само приложение, и все вспомогательные файлы —
`fsclient-core.dll`, `fs_backend.dll`, иконка и `updater.exe`. При запуске
лаунчер распаковывает их в `%ProgramFiles%\fsclient\app\` и запускает ядро
оттуда. Отдельно `updater.exe` распространять не нужно: он будет извлечён
из встроенного ресурса. EXE сам запросит права администратора через UAC,
а `updater.exe` права не запрашивает — он наследует их от уже elevated
лаунчера.

## Сборка с нуля

Нужны **.NET SDK 10 (Windows Desktop)** и **MinGW-w64** (`g++.exe`, `windres.exe`,
`objdump.exe` должны быть в `PATH`). Больше ничего предварительно собирать не нужно.

```bat
git clone <ваш-репозиторий> fsclient
cd fsclient
build.bat
```

`build.bat` сам:

1. соберёт `cpp\fs_backend.dll` из `cpp\backend.cpp`;
2. опубликует WPF-ядро из C#/XAML-файлов в `build-publish\`;
3. соберёт **`updater.exe` из `updater.cpp`** в служебную папку `build-updater\`;
4. встроит updater и все остальные файлы в `dist\fsclient.exe` ресурсами;
5. проверит, что в готовом EXE нет внешних DLL MinGW.

### Где лежит исходник updater

- **`updater.cpp`** в корне репозитория — полный исходный код `updater.exe`.
- Отдельный EXE в репозитории не хранится: `build-updater\` создаётся сборкой
  и добавлен в `.gitignore`.
- Готовый updater попадает внутрь `fsclient.exe` как `107 RCDATA`.
- `launcher.cpp` распаковывает его в `%ProgramFiles%\fsclient\app\updater.exe`.

Для быстрой отладки WPF-части без лаунчера можно сделать `dotnet run`, но для
полного приложения нужен именно `build.bat`.

## Настройки

Кнопка ⚙ в правом верхнем углу окна открывает настройки с двумя разделами:

- **Общие** — папка данных. По умолчанию `%ProgramFiles%\fsclient\data`
  (создаётся при первом запуске). В ней лежат `releases\`, `plugins\`, `logs\`
  и `assets\`. При смене папки всё содержимое сначала копируется в новую
  директорию и проверяется, и только после этого старая папка удаляется.
  Сам `settings.json` остаётся в `%LOCALAPPDATA%\fsclient`, чтобы
  лаунчер знал, где искать данные после перезапуска. При первом запуске
  новой версии уже скачанные релизы переносятся из старой папки автоматически.
- **Внешний вид** — степень размытия фона (0–30), заголовок окна и своя
  картинка заднего фона. Файл фона копируется в `assets\` папки данных.

В `logs\launch.log` пишется лог лаунчера; при каждом запуске файл обрезается
до последних трёх сессий.

## TG WS Proxy

Страница открывается карточкой **TG-WS-Proxy** в боковом меню. Лаунчер работает
только с официальными сборками Flowseal:

- версии берутся из GitHub API репозитория `Flowseal/tg-ws-proxy`, скачивается
  `TgWsProxy_windows.exe` (для ARM64 — `_windows_arm64.exe`);
- каждая версия лежит в `tg-ws-proxy\releases\<версия>\` папки данных, рядом с
  exe создаётся портативная папка `TgWsProxy_data` с `config.json`;
- лаунчер сам пишет конфиг (адрес, порт, secret, DC, CF/H2) и отключает
  диалоги первого запуска и проверки обновлений оригинального приложения;
- запуск/остановка идут через `fs_tgws_start` / `fs_tgws_stop` в
  `cpp/fs_backend.dll`: процесс привязывается к Job Object, поэтому закрытие
  лаучера не оставляет дочерние процессы;
- на странице доступны перезапуск, копирование и открытие `tg://proxy`,
  открытие папки/лога, генерация нового secret и журнал `proxy.log`.

Изменения конфига применяются после перезапуска прокси. Смена папки данных в
настройках недоступна, пока zapret или TG WS Proxy активны.

## Сборка

Нужны:

- **.NET SDK 10**;
- **MinGW-w64** (`g++`, `windres`, `objdump`) — ищется в `PATH`, либо в WinGet-пакете
  `BrechtSanders.WinLibs.POSIX.UCRT`.

Из корня репозитория:

```bat
build.bat
```

Скрипт последовательно:

1. Компилирует `cpp\backend.cpp` → `cpp\fs_backend.dll`.
2. Публикует framework-dependent приложение во временную папку `build-publish\`.
3. Вшивает все файлы приложения ресурсами в `launcher.cpp` и собирает
   единственный `dist\fsclient.exe` — с проверкой .NET 10 и переходом на
   официальный сайт, если runtime отсутствует. Рантайм MinGW (в том числе
   `libwinpthread-1.dll`) вшит статически, поэтому на целевом ПК не нужны
   никакие DLL от MinGW; сборка проверяет это через `objdump -p`.

Результат — один `dist\fsclient.exe` для публикации в релизе.

Для самообновления создайте в репозитории из `UpdateRepo` релиз с тегом
`v1.3.0` и приложите к нему ассет с именем ровно `fsclient.exe`. Другое имя
или тег без `v` проверка обновления не примет.

## Совместимость с zapret 1.x и 2.x

Лаунчер работает с обоими поколениями движка:

| | 1.x | 2.x (RC и стабильные) |
|---|---|---|
| Исполняемый файл | `bin\winws.exe` | `bin\winws2.exe` |
| Стратегии | `--dpi-desync=*` | `--lua-desync=*` + `--lua-init` |
| Доп. папка | — | `lua\` |
| Служба | `zapret`, registry `zapret-discord-youtube` | без изменений |

Парсер батников понимает оба исполняемых файла, пустые строки в многострочных
командах 2.x и переменную `%LUA%`. Состояние, остановка и удаление осиротевших
процессов тоже учитывают `winws2.exe`. При установке службы для 2.x добавляется
`--chdir`, как в оригинальном `service.bat`.

В списке релизов пре-релизы 2.x показываются с пометкой **«пре-релиз»**, но
по умолчанию выбирается последний стабильный релиз (сейчас 1.10.4). Когда 2.x
выйдет в стабильный релиз, он станет рекомендуемым автоматически. Ранее
выбранный пользователем тег всегда сохраняется.

## Память

При скрытии окна в трей включается «режим сна» WPF-слоя: отключается размытие
фона, `VisualBrush` матовых панелей и декодированная копия `background.jpg`,
затем выполняется сборка мусора и `EmptyWorkingSet`. Опрос состояния продолжается
с интервалом 10 с (вместо 1,8 с), закачки и служба не прерываются. При открытии
окна всё восстанавливается. Это снижает видимый в «Диспетчере задач» `Working Set`, но
не уменьшает `Commit` — для полной выгрузки нужен отдельный трей-процесс.

## Структура

```text
launcher.cpp                    Единый EXE: проверка .NET 10 и распаковка приложения
App.xaml(.cs)                   Запуск, single instance, тема
MainWindow.xaml(.cs)            Интерфейс, трей, логика состояний
Backend.cs                      P/Invoke, GitHub API, стратегии, служба, TG WS
TgWsProxyService.cs             Версии, config.json и ссылки TG WS Proxy
BundledResources.cs             Резервная распаковка DLL/иконки
DarkTrayMenuRenderer.cs         Кастомное меню в трее
FrostedControls.cs              Матовое стекло и плавный скруглённый прогресс
Styles.xaml                     Палитра и стили
StrategyDialog / ConfirmDialog  Модальные окна
app.manifest                    Права администратора, DPI
fsclient.csproj                 Проект .NET 10 WPF (версия 1.3.0)
cpp/                            Исходники бэкенда (DLL создаётся сборкой)
assets/                         Фон, иконка, скриншот
build.bat                       Сборка DLL, публикация и единого EXE
dist/                           Один fsclient.exe (не хранится в git)
CHANGELOG.md                    Список изменений для релиза
```

## Что не лежит в репозитории

`bin/`, `obj/`, `dist/`, `build-publish/`, `launcher.rc`, `launcher.res`,
`cpp/*.a`, `cpp/fs_backend.dll`, `releases/`, `plugins/`, `tg-ws-proxy/` —
генерируется локально или скачивается лаунчером.
